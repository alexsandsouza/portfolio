CONCEITO RÁPIDO: O QUE É GIT E GITHUB? 
Git 
Sistema de controle de versão local. Rastreia 
todas as alterações feitas no código, permite 
voltar a versões anteriores e trabalhar em equipe 
sem conflitos. 
GitHub 
Plataforma online que hospeda repositórios Git. 
Funciona como uma "nuvem de código": permite 
colaboração, portfólio público e publicação de 
sites via GitHub Pages. 
Os 4 comandos Git que você mais usará: 
Tag / Propriedade 
Descrição / Uso 
git init 
Inicializa um repositório Git na pasta atual. Executado uma única vez por 
projeto. 
git add . 
Adiciona todos os arquivos modificados à área de staging (prontos para o 
commit). 
git commit -m 
"msg" 
Salva um snapshot permanente das alterações com uma mensagem 
descritiva. 
git push 
Envia os commits locais para o repositório remoto (GitHub).

PASSO 2 - CONFIGURANDO O GIT 
Abra o Terminal (no VS Code: Terminal > New Terminal) e configure seu nome e e-mail. Isso 
precisa ser feito apenas uma vez por computador: 
 
 
# Configuração global do Git (faça uma vez no computador) 
git config --global user.name "Seu Nome Completo" 
git config --global user.email "seu@email.com" 
 
# Confirme as configurações:git config --global --list 
 
  Verificando se o Git está instalado 
Digite git --version no terminal. Se aparecer a versão (ex: git version 2.43.0), está instalado. 
Caso contrário, baixe em https://git-scm.com 
PASSO 3 - CRIANDO O REPOSITÓRIO NO GITHUB 
1 
Acesse github.com 
Se ainda não tiver conta, clique em "Sign up" e crie uma conta gratuita com seu e-mail. 
 
2 
Crie um novo repositório 
Clique no botão "+" (canto superior direito) > "New repository". 
 
3 
Configure o repositório 
Repository name: portfolio-seu-nome (ex: portfolio-joao-silva). Visibilidade: Public 
(obrigatório para GitHub Pages gratuito). NÃO marque "Initialize this repository" — o 
código virá do seu computador. 
 
4 
Copie a URL do repositório 
Após criar, copie a URL HTTPS exibida na tela (ex: https://github.com/usuario/portfolio-
seu-nome.git). 
 
⚠  Nome do repositório 

Recomendação: use apenas letras minúsculas, hífens e sem espaços. Exemplo: portfolio-ana-
silva. O nome aparece na URL do GitHub Pages, então escolha algo legível. 
PASSO 4 - VERSIONANDO E ENVIANDO O CÓDIGO 
No terminal do VS Code (com a pasta portfolio aberta), execute os comandos na ordem: 
4.1  Inicializando o repositório local 
 
 
# 1. Acesse a pasta do projeto (se necessário) 
cd caminho/para/portfolio 
 
# 2. Inicializa o Git na pasta 
git init 
 
# 3. Adiciona todos os arquivos ao staging 
git add . 
 
# 4. Cria o primeiro commit 
git commit -m "feat: portfólio pessoal concluído - HTML5 + CSS3" 
 
# 5. Renomeia a branch para 'main' 
git branch -M main 
 
# 6. Conecta ao repositório remoto (use SUA URL) 
git remote add origin https://github.com/SEU-USUARIO/portfolio-seu-nome.git 
 
# 7. Envia o código para o GitHubgit push -u origin main 
 
  Autenticação no GitHub 
Na primeira vez que fizer git push, o VS Code ou o terminal pedirá login no GitHub. Use seu 
usuário e senha ou configure um token de acesso pessoal em github.com > Settings > 
Developer settings > Personal access tokens. 
 
4.2  Verificando o envio 
 
Acesse github.com/SEU-USUARIO/portfolio-seu-nome no navegador. Você deve ver todos os seus 
arquivos listados no repositório. 
 
 
# Comandos úteis para verificar o status: 
git status          # mostra arquivos modificados e staged 
git log --oneline   # lista os commits feitosgit remote -v       # mostra o 
repositório remoto configurado 
 
PASSO 5 - PUBLICANDO COM GITHUB PAGES 
O GitHub Pages publica automaticamente arquivos HTML/CSS/JS de um repositório como um site 
público e gratuito. 
 
1 
Acesse as configurações do repositório 
No GitHub, dentro do repositório, clique em Settings (ícone de engrenagem). 
 

2 
Encontre o GitHub Pages 
No menu lateral esquerdo, clique em Pages. 
 
3 
Configure a fonte 
Em "Source", selecione: Deploy from a branch. Em "Branch", selecione: main e pasta 
/(root). Clique em Save. 
 
4 
Aguarde a publicação 
A publicação leva entre 1 e 3 minutos. Atualize a página e o link aparecerá no topo da 
seção Pages: 
 
 
# Formato da URL do seu portfólio publicado: 
https://SEU-USUARIO.github.io/portfolio-seu-nome 
 
# Exemplo real:https://joao-silva.github.io/portfolio-joao-silva 
 
✅  Portfólio publicado! 
Seu portfólio agora está acessível de qualquer dispositivo, em qualquer lugar do mundo, com 
URL permanente. Compartilhe nos seus perfis do LinkedIn e GitHub! 
 
PASSO 6 - ATUALIZANDO O PORTFÓLIO APÓS MUDANÇAS 
Sempre que fizer alterações no portfólio, use este fluxo para atualizar o GitHub Pages: 
 
 
# Salve os arquivos no VS Code (Ctrl+S) 
 
# Adicione as alterações ao staging 
git add . 
 
# Crie um novo commit descrevendo o que foi alterado 
git commit -m "fix: corrige layout mobile da seção projetos" 
 
# Envie para o GitHub 
git push 
# O GitHub Pages atualiza automaticamente em 1-2 minutos 
 
Boas práticas de mensagens de commit: 
Prefixo Quando usar — exemplo 
feat: 
Nova funcionalidade — feat: adiciona seção de certificados 
fix: 
Correção de erro — fix: corrige link quebrado no footer 
style: 
Ajuste visual — style: melhora responsividade do header 
docs: 
Documentação — docs: adiciona README ao repositório 
refactor: 
Refatoração — refactor: reorganiza estrutura do CSS

ERROS COMUNS NESTA AULA 
Erro comum Como corrigir 
git push recusa (error: rejected) Use git pull origin main --allow-unrelated-histories antes do 
push. Isso ocorre quando o repositório remoto foi 
inicializado com arquivos. 
GitHub Pages mostra página em 
branco 
Confirme que o arquivo principal se chama exatamente 
index.html (minúsculas) na raiz do repositório. 
GitHub Pages não encontra o CSS O caminho no HTML deve ser href="css/style.css" — 
caminho relativo, sem /. Caminhos absolutos não 
funcionam no GitHub Pages gratuito. 
Imagens não aparecem no GitHub 
Pages 
Confirme que os nomes dos arquivos de imagem são iguais 
aos caminhos no HTML. O Linux (servidor do GitHub) 
diferencia maiúsculas de minúsculas: foto.JPG e foto.jpg 
são arquivos diferentes. 
Branch rejeitada (not found) Execute git branch -M main para garantir que a branch se 
chama main antes do push.
